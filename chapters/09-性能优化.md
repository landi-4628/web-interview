## 2. 虚拟列表（el-table / 长列表）

**问题**：10000 行 DOM，滚动卡死。  
**思路**：只渲染可视区域 + 上下缓冲的几十条。

```javascript
// 伪代码
const itemHeight = 40;
const visibleCount = Math.ceil(viewportHeight / itemHeight) + 2;
const start = Math.floor(scrollTop / itemHeight);
const end = start + visibleCount;
const slice = fullList.slice(start, end);
// 外层容器 height = fullList.length * itemHeight（撑开滚动条）
// 内层 translateY(start * itemHeight) 偏移
```

## 5. SSR 服务端渲染

**问题**：SPA 首屏白屏，搜索引擎抓不到内容。  
**思路**：服务端先渲染出完整 HTML，客户端再"激活"（hydration）。

### Vue 项目（Nuxt 3）

```bash
npx nuxi@latest init ssr-app
cd ssr-app
npm run dev
```

```vue
<!-- pages/index.vue -->
<template>
  <div>
    <h1>{{ title }}</h1>
    <p>{{ description }}</p>
  </div>
</template>

<script setup>
const { data } = await useFetch('/api/content');
const title = computed(() => data.value?.title ?? '加载中');
const description = computed(() => data.value?.description ?? '');
</script>
```

**效果**：浏览器拿到的是已渲染的 HTML，FCP（首次内容绘制）从 3s 降到 0.5s。

### React 项目（Next.js）

```bash
npx create-next-app@latest ssr-react
```

```jsx
// app/page.js
async function getData() {
  const res = await fetch('https://api.example.com/data');
  return res.json();
}

export default async function Page() {
  const data = await getData();
  return <main><h1>{data.title}</h1></main>;
}
```

### SSR vs SSG vs CSR 对比

| 方案 | 首屏速度 | SEO | 服务压力 | 适用场景 |
| --- | --- | --- | --- | --- |
| CSR（客户端渲染）| 慢 | 差 | 小 | 后台系统、需登录的页面 |
| SSR（服务端渲染）| 快 | 好 | 大 | 内容型网站、电商详情页 |
| SSG（静态生成）| 最快 | 好 | 无 | 博客、文档、官网 |

### hydration（激活）原理

1. 服务端把组件树渲染成 HTML 字符串，返回给浏览器
2. 浏览器解析 HTML 快速显示内容
3. 浏览器下载并执行 JS Bundle
4. JS 执行时"接管"已有的 DOM，进行事件绑定和响应式处理

```html
<!-- 服务端输出的 HTML 已包含内容 -->
<div id="app">
  <h1>这是服务端渲染的内容</h1>
</div>
<script src="/bundle.js"></script>
<!-- hydration 后，JS 接管 DOM，不重新渲染 -->
```

## 6. Preload 与 Prefetch 预加载

### Preload（预加载）—— 当前导航需要

**告诉浏览器**：这个资源在当前页面**一定**会用到，立刻下载。

```html
<!-- 预加载字体 -->
<link rel="preload" href="/fonts/main-font.woff2" as="font" crossorigin />

<!-- 预加载关键 CSS -->
<link rel="preload" href="/styles/critical.css" as="style" />

<!-- 预加载首屏图片 -->
<link rel="preload" href="/images/hero.webp" as="image" />
```

```javascript
// JS 中动态预加载
const link = document.createElement('link');
link.rel = 'preload';
link.as = 'script';
link.href = '/js/big-module.js';
document.head.appendChild(link);
```

**使用场景**：
- 首屏必须的大图片
- 关键 CSS 文件
- 首屏依赖的 JS 模块
- 字体文件

### Prefetch（预获取）—— 未来导航可能用到

**告诉浏览器**：这个资源**可能**会用到，在空闲时下载。

```html
<!-- 预获取下一个页面需要的资源 -->
<link rel="prefetch" href="/js/vendor.js" />
<link rel="prefetch" href="/chunks/chapter-3.js" />

<!-- 预获取图片 -->
<link rel="prefetch" href="/images/next-page-banner.jpg" />
```

```javascript
// 当鼠标悬停在链接上时预获取
document.querySelectorAll('a[data-prefetch]').forEach(link => {
  link.addEventListener('mouseenter', () => {
    const url = link.href;
    if (url.startsWith(window.location.origin)) {
      // 预获取同域页面
      fetch(url, { priority: 'low' });
    }
  }, { once: true });
});
```

### preload 与 prefetch 区别

| 特性 | preload | prefetch |
| --- | --- | --- |
| 下载时机 | 立即下载 | 空闲时下载 |
| 优先级 | 高（当前页面必需） | 低（未来可能用到） |
| 缓存 | 同普通资源 | 进入磁盘缓存 |
| 使用场景 | 首屏关键资源 | 下个页面资源 |

### 实际案例：Vue 项目优化

```html
<!-- index.html -->
<head>
  <!-- preload 首屏必须的资源 -->
  <link rel="preload" href="/fonts/SourceHanSans.woff2" as="font" crossorigin />
  <link rel="preload" href="/css/chunk-vendors.css" as="style" />
  <link rel="preload" href="/images/logo.svg" as="image" />

  <!-- prefetch 用户可能访问的路由资源 -->
  <link rel="prefetch" href="/js/views-About.js" />
  <link rel="prefetch" href="/js/views-Contact.js" />
  <link rel="prefetch" href="/images/banner-about.jpg" />
</head>
```

### 效果对比

```
无优化：
  HTML ↓  JS下载+解析+执行 ↓ 图片加载 → 用户看到内容 (4s)

preload 优化后：
  HTML ↓  资源并行下载 ↓ 执行 → 用户看到内容 (1.5s)

prefetch 优化后：
  首屏(1.5s) → 用户操作 → 预取资源已缓存 → 次级页面秒开 (0.3s)
```
