## 1. 输入 URL 到页面展示

**流程记忆**：DNS → TCP → TLS → HTTP → 解析 HTML/CSS → 渲染树 → 布局 → 绘制 → 合成

### 案例：你在公司打开 `https://example.com/page`

1. 浏览器查 DNS，得到服务器 IP  
2. 与服务器 TCP 三次握手，HTTPS 再 TLS 握手  
3. 发 GET 请求，带 Cookie、User-Agent 等  
4. 收到 HTML，边下边解析，遇到 `<link css>`、`<script>` 可能阻塞或异步加载  
5. DOM + CSSOM → Render Tree → Layout（算位置大小）→ Paint → GPU 合成层

## 2. 回流 & 重绘

| | 回流 reflow | 重绘 repaint |
| --- | --- | --- |
| 触发 | 宽高、位置、display、读 offsetTop 等 | 颜色、背景、visibility |
| 代价 | 大（可能整页重算布局） | 相对小 |

```javascript
// ❌ 坏：循环里反复读布局属性，强制同步布局
for (let i = 0; i < 100; i++) {
  el.style.width = box.offsetWidth + 1 + 'px'; // 读 + 写 交替触发回流
}

// ✅ 好：批量改 class，或用 transform（只走合成层）
el.classList.add('expanded');
// CSS: .expanded { transform: scale(1.1); }
```

## 3. 强缓存 vs 协商缓存

**案例：第二次打开官网**

- 第一次：服务器返回 `Cache-Control: max-age=31536000`，浏览器把 JS 存本地  
- 一周内再访问：强缓存命中，**不发请求**，直接用磁盘文件  
- 若 `max-age` 过期：带 `If-None-Match: "abc123"`（ETag）问服务器  
- 文件未变 → **304**，继续用本地；变了 → **200** 下载新文件

## 4. 跨域

**同源**：协议 + 域名 + 端口 全相同。

```javascript
// 前端 localhost:5173 请求 api.example.com → 跨域

// 解决 1：开发环境代理（Vite）
// vite.config.js
// server: { proxy: { '/api': { target: 'http://localhost:3000', changeOrigin: true } } }
// 页面请求 /api/user → 实际打到 3000，浏览器认为同源

// 解决 2：后端 CORS
// Access-Control-Allow-Origin: https://your-site.com
// Access-Control-Allow-Credentials: true
```

**带自定义头 + Cookie 的 POST** 会先触发 **OPTIONS 预检**，通过后再发真实请求。
