## 1. el-table 几千条数据卡顿？

**原因**：DOM 节点过多，滚动/重排成本高。

**方案**：

1. **分页**：后端分页，每页 20～50（业务最常见）  
2. **虚拟滚动**：只渲染可视行（`el-table-v2` 或第三方 virtual-scroll）  
3. **减少列复杂度**：少嵌套组件、少自定义 render  
4. **固定列宽**：避免频繁自动算列宽触发回流  

---

## 2. 首屏白屏时间过长怎么排查？

**步骤**：

1. Lighthouse / Performance：看 FCP、LCP、TBT  
2. Network：是否 JS bundle 过大、是否串行请求接口瀑布  
3. 是否阻塞渲染的同步 script、是否未做路由懒加载  
4. 图片是否过大、是否缺骨架屏导致「看起来白」  

**优化**：拆包、CDN、预加载关键资源、接口合并、SSR/SSG（若 SEO 需要）。

---

## 3. 打包体积过大如何瘦身？

- `rollup-plugin-visualizer` / `webpack-bundle-analyzer` 找大头  
- 按需引入 UI 库、替换重量级依赖  
- `manualChunks` 拆 vendor  
- 生产环境 source map 关掉或外置  
- 开启 gzip/brotli

## 5. 大屏尺寸适配怎么做？（数据可视化/监控大屏）

大屏尺寸适配是**数据可视化、监控大屏、展厅展示**等场景的**核心技术难点**。与移动端适配相比，大屏适配面临更大尺寸、更高分辨率、多屏拼接等特殊挑战。

### 5.1 大屏适配 vs 移动端适配的核心区别

| 维度 | 移动端适配 | 大屏适配 |
|------|------------|----------|
| **屏幕尺寸** | 小屏（手机） | 超大屏（电视墙、拼接屏） |
| **分辨率** | 相对固定（2x、3x） | 多变（4K、8K、多屏拼接） |
| **交互方式** | 触摸为主 | 鼠标/遥控器/触摸混合 |
| **使用距离** | 近距离（30-50cm） | 远距离（2-5米） |
| **内容密度** | 信息精简 | 信息密集，多图表联动 |
| **刷新频率** | 普通（60Hz） | 可能要求高刷新率（120Hz+） |
| **性能要求** | 中等 | 极高（大量动画、数据实时更新） |

### 5.2 大屏适配的核心挑战

1. **超大分辨率**：4K（3840×2160）、8K（7680×4320）等超高分辨率
2. **多屏拼接**：多个屏幕物理拼接成一个显示区域
3. **浏览器限制**：部分浏览器对超大Canvas/渲染性能有限制
4. **字体清晰度**：超大屏上字体边缘模糊、锯齿问题
5. **图表缩放**：数据可视化图表在高分辨率下失真

### 5.3 技术方案对比

#### 方案一：CSS适配方案（推荐用于布局型大屏）

#### 方案二：JS动态适配方案（推荐用于数据可视化大屏）

```javascript
// 大屏适配工具类
class LargeScreenAdapter {
  constructor(designWidth = 1920, designHeight = 1080) {
    this.designWidth = designWidth
    this.designHeight = designHeight
    this.scaleX = 1
    this.scaleY = 1
    this.init()
  }

  init() {
    this.calculateScale()
    window.addEventListener('resize', () => this.calculateScale())
  }

  calculateScale() {
    const { innerWidth, innerHeight } = window
    
    // 保持比例缩放，避免拉伸变形
    const scaleX = innerWidth / this.designWidth
    const scaleY = innerHeight / this.designHeight
    const scale = Math.min(scaleX, scaleY) // 取较小值保证完全显示
    
    this.scaleX = scale
    this.scaleY = scale
    
    // 应用到根元素
    document.documentElement.style.setProperty('--scale', scale)
    document.documentElement.style.setProperty('--scale-x', scaleX)
    document.documentElement.style.setProperty('--scale-y', scaleY)
    
    // 计算居中偏移
    const offsetX = (innerWidth - this.designWidth * scale) / 2
    const offsetY = (innerHeight - this.designHeight * scale) / 2
    document.documentElement.style.setProperty('--offset-x', `${offsetX}px`)
    document.documentElement.style.setProperty('--offset-y', `${offsetY}px`)
  }

  // 将设计稿尺寸转换为实际尺寸
  pxToReal(px, dimension = 'x') {
    return px * (dimension === 'x' ? this.scaleX : this.scaleY)
  }

  // 适配字体大小（防止过小看不清）
  adaptFontSize(baseSize = 14) {
    const scale = Math.min(this.scaleX, this.scaleY)
    return Math.max(baseSize, baseSize * scale)
  }
}

// 使用
const adapter = new LargeScreenAdapter(3840, 2160) // 4K设计稿
```

#### 案例二：多屏拼接适配方案

**场景**：视频墙多屏拼接显示，需要处理屏幕缝隙和内容连续性。

```javascript
// 多屏拼接适配器
class MultiScreenAdapter {
  constructor(screenConfig) {
    // screenConfig: { cols: 3, rows: 2, gap: 24 }
    this.config = screenConfig
    this.totalWidth = 0
    this.totalHeight = 0
    this.calculateTotalSize()
  }

  calculateTotalSize() {
    // 假设每个屏幕都是1920×1080
    const { cols, rows, gap } = this.config
    this.totalWidth = cols * 1920 + (cols - 1) * gap
    this.totalHeight = rows * 1080 + (rows - 1) * gap
  }

  // 获取某个屏幕上的元素位置
  getScreenPosition(screenCol, screenRow, elementX, elementY) {
    const { gap } = this.config
    const screenX = screenCol * (1920 + gap)
    const screenY = screenRow * (1080 + gap)
    
    return {
      x: screenX + elementX,
      y: screenY + elementY,
      // 标记是否在屏幕缝隙区域
      inGap: this.isInGapArea(screenX + elementX, screenY + elementY)
    }
  }

  isInGapArea(x, y) {
    const { cols, rows, gap } = this.config
    
    // 检查是否在水平缝隙
    for (let col = 1; col < cols; col++) {
      const gapStartX = col * 1920 + (col - 1) * gap
      const gapEndX = gapStartX + gap
      if (x >= gapStartX && x < gapEndX) return true
    }
    
    // 检查是否在垂直缝隙
    for (let row = 1; row < rows; row++) {
      const gapStartY = row * 1080 + (row - 1) * gap
      const gapEndY = gapStartY + gap
      if (y >= gapStartY && y < gapEndY) return true
    }
    
    return false
  }

  // 内容避让缝隙算法
  avoidGap(element) {
    const { x, y, width, height } = element
    const { gap } = this.config
    
    // 检查元素的四个角是否在缝隙中
    const corners = [
      { x, y },
      { x: x + width, y },
      { x, y: y + height },
      { x: x + width, y: y + height }
    ]
    
    const inGapCorner = corners.find(corner => this.isInGapArea(corner.x, corner.y))
    
    if (inGapCorner) {
      // 如果在缝隙中，向右下角微调
      return {
        x: x + gap,
        y: y + gap,
        width: width - gap,
        height: height - gap
      }
    }
    
    return element
  }
}
```

### 5.5 大屏适配最佳实践

#### 1. 设计原则
- **保持比例**：始终等比例缩放，避免拉伸变形
- **字体可读**：设置最小字体大小，保证远距离可读
- **性能优先**：使用Canvas/WebGL代替DOM渲染大量元素
- **渐进增强**：先保证核心功能，再添加高级效果

```javascript
// 根据分辨率加载不同尺寸的图片
function loadOptimizedImage(url, sizes = {
  'default': '1920w',
  '3840': '3840w', // 4K
  '7680': '7680w'  // 8K
}) {
  const screenWidth = window.innerWidth

}
```

#### 4. 性能监控与优化
```javascript
// 大屏性能监控
class LargeScreenPerformance {
  constructor() {
    this.fps = 0
    this.frameCount = 0
    this.lastTime = performance.now()
    this.startMonitoring()
  }

  startMonitoring() {
    const checkFPS = () => {
      this.frameCount++
      const currentTime = performance.now()
      
      if (currentTime - this.lastTime >= 1000) {
        this.fps = Math.round((this.frameCount * 1000) / (currentTime - this.lastTime))
        this.frameCount = 0
        this.lastTime = currentTime
        
        // 性能预警
        if (this.fps < 30) {
          console.warn(`大屏性能警告：当前FPS仅${this.fps}`)
          this.triggerPerformanceOptimization()
        }
      }
      
      requestAnimationFrame(checkFPS)
    }
    
    checkFPS()
  }

  triggerPerformanceOptimization() {
    // 动态降低视觉效果
    document.documentElement.style.setProperty('--animation-speed', '0.5s')
    
    // 减少重绘
    const charts = document.querySelectorAll('.chart-container')
    charts.forEach(chart => {
      chart.style.willChange = 'transform'
    })
    
    // 暂停非关键动画
    document.querySelectorAll('.secondary-animation').forEach(el => {
      el.style.animationPlayState = 'paused'
    })
  }

  // 内存监控
  monitorMemory() {
    if (performance.memory) {
      const { usedJSHeapSize, totalJSHeapSize } = performance.memory
      const memoryUsage = (usedJSHeapSize / totalJSHeapSize) * 100
      
      if (memoryUsage > 80) {
        console.warn(`内存使用率过高：${memoryUsage.toFixed(1)}%`)
        this.cleanupUnusedResources()
      }
    }
  }

  cleanupUnusedResources() {
    // 清理不显示的图表
    document.querySelectorAll('.chart-container:hidden').forEach(container => {
      const chart = echarts.getInstanceByDom(container)
      if (chart) chart.dispose()
    })
    
    // 清理图片缓存
    const images = document.querySelectorAll('img[data-lazy]')
    images.forEach(img => {
      if (!img.checkVisibility()) {
        img.src = '' // 释放内存
      }
    })
  }
}
```

### 5.6 常见面试题

#### Q1：大屏适配和移动端适配的主要区别是什么？
**考察点**：理解不同场景下的适配需求差异

**回答要点**：
1. **尺寸差异**：移动端是小屏触摸，大屏是超大屏远距离观看
2. **性能要求**：大屏需要处理更高分辨率、更多数据可视化元素
3. **交互方式**：移动端触摸为主，大屏可能使用鼠标、遥控器等
4. **使用场景**：移动端是个人设备，大屏是公共展示设备

#### Q2：如何处理4K/8K等高分辨率大屏的字体模糊问题？
**考察点**：高分辨率下的字体渲染技术

**回答要点**：
1. **字体放大策略**：基于屏幕尺寸动态调整字体大小
2. **字体平滑处理**：使用`font-smoothing`和`text-rendering`优化
3. **矢量字体优先**：使用SVG图标和矢量字体代替位图
4. **抗锯齿处理**：适当使用`text-shadow`增加字体清晰度

#### Q3：如何优化大屏数据可视化性能？
**考察点**：性能优化和渲染技术

**回答要点**：
1. **Canvas/WebGL优先**：使用Canvas或WebGL渲染图表而非DOM
2. **数据分片加载**：大数据集分片加载和渲染
3. **防抖节流**：对resize等高频事件进行防抖处理
4. **离屏渲染**：复杂图表使用离屏Canvas预渲染

#### Q4：多屏拼接时如何处理屏幕缝隙？
**考察点**：多屏显示的特殊问题处理

**回答要点**：
1. **内容避让算法**：检测并避开屏幕物理缝隙区域
2. **视觉补偿**：在缝隙处添加视觉过渡效果
3. **硬件校准**：配合硬件进行像素级对齐
4. **测试验证**：实际多屏环境下测试显示效果

#### Q5：大屏项目如何进行测试？
**考察点**：测试策略和质量保证

**回答要点**：
1. **多分辨率测试**：在不同分辨率设备上测试
2. **性能压力测试**：模拟大数据量下的性能表现
3. **远距离可读性测试**：实际观看距离下测试可读性
4. **长时间运行测试**：测试内存泄漏和稳定性

### 5.7 大屏适配检查清单

在开发大屏项目前，对照检查以下问题：

- [ ] **分辨率适配**：是否支持4K/8K等高分辨率？
- [ ] **字体可读性**：远距离观看是否清晰？
- [ ] **性能优化**：大量数据可视化时是否流畅？
- [ ] **浏览器兼容**：目标浏览器是否支持所需特性？
- [ ] **多屏支持**：是否考虑多屏拼接场景？
- [ ] **交互适配**：是否支持鼠标、触摸、遥控器等多种交互？
- [ ] **内容密度**：信息展示是否过于密集或稀疏？
- [ ] **色彩对比**：大屏环境下色彩对比是否足够？
- [ ] **动画优化**：动画是否平滑且不影响性能？
- [ ] **测试覆盖**：是否在不同尺寸设备上充分测试？

| `hospital-basic-web` | 基座应用 | 负责登录、用户信息、菜单权限、子应用注册 |
| `data-web` | 子应用（数据管理平台） | 作为子应用被基座加载，独立运行也有完整功能 |

### qiankun 框架与普通应用的本质区别

| 维度 | 普通应用 | qiankun 子应用 |
| --- | --- | --- |
| 入口方式 | 直接加载 `index.html` | 基座通过 fetch 加载子应用入口 JS，动态执行 |
| 路由管理 | 主应用独享路由，直接 `router.push()` | 基座和子应用各自管理路由，通过 URL 划分作用域 |
| JS 沙箱 | 无隔离，所有全局变量共享 | JS 沙箱（SnapshotSandbox / ProxySandbox），子应用全局变量不污染主应用 |
| CSS 隔离 | 全局样式互相覆盖 | Shadow DOM 或 CSS Modules / BEM 命名隔离 |
| 生命周期 | `main.js` → `new Vue()` | 必须导出 `bootstrap / mount / unmount` 三个钩子 |
| 状态共享 | 直接引用同一个 Vuex/Pinia | 通过 `initGlobalState` 或 `props` 传参，禁止直接引用 |
| 依赖加载 | 所有依赖打包进 bundle | 子应用应使用 `externals`，由基座或 CDN 提供共享依赖 |
| 独立运行 | 需要完整的登录和路由守卫 | 有 `window.__POWERED_BY_QIANKUN__` 区分环境，走不同初始化逻辑 |

**1. main.js 入口区别**

普通应用：

```javascript
// 普通应用 main.js

import App from './App.vue'
import router from './router'
import store from './store'

new Vue({
  router,
  store,
  render: h => h(App)
```

```javascript
  const { container } = props
  instance = new Vue({
    router,
    store,
    render: h => h(App)
  }).$mount(container ? container.querySelector('#app') : '#app')

// qiankun 约定的生命周期

  console.log('[子应用] bootstrap')

}

  console.log('[子应用] unmount')

  instance = null
}

// 独立运行（不走 qiankun 时直接渲染）

}
```

### 鉴权流程（路由守卫）

**基座应用** `src/permission.js` 完整代码解析：

```javascript
router.beforeEach(async(to, from, next) => {
  NProgress.start()

  // 1. 优先处理单点登录（SSO）ticket 校验
  const ticket = getQueryString('ticket')
  if (ticket) {
    // 清空 URL 中的 ticket 参数，避免刷新重复触发
    window.history.replaceState(null, null, `${window.location.pathname}${window.location.hash}`)
    store.dispatch('user/thirdPartyAuthority', { authority: ticket, client: 1 })
      .then((res) => {
        if (Number(res.isFirstLanding) === 0) {
          next({ path: '/' })           // 已注册过 → 去首页
        } else {
          next({ name: 'resetPassword', query: { actionType: 'firstLanding' }}) // 首次 → 重置密码
        }
      }).catch(_ => next(`/login`))
    return
  }

  // 2. 普通 Token 校验
  const hasToken = getToken()  // 从 Cookie 读取

  if (hasToken) {
    // 3. 已登录用户访问登录页 → 跳首页
    if (to.path === '/login') {
      next({ path: '/' })
      NProgress.done()
    } else {
      // 4. 检查是否已有 roles（避免每次路由切换都重新请求）
      const hasRoles = store.getters.roles && store.getters.roles.length > 0
      if (hasRoles) {
        next()  // 直接放行
      } else {
        // 5. 首次加载：拉取用户信息 + 动态生成路由 + 启动 qiankun
        try {
          const roles = await store.dispatch('user/getInfo')       // 拉取用户信息
          await store.dispatch('permission/generateRoutes', { roles }) // 生成菜单路由
          if (!isStartQiankunModule) {
            start()            // 启动 qiankun，注册子应用生命周期
            isStartQiankunModule = true
          }
          next({ ...to, replace: true }) // 重新进入，让 router 匹配新注入的路由
        } catch (error) {
          await store.dispatch('user/resetToken')  // 清除过期 token
          Message.error(error || 'Has Error')
          next(`/login`)
          NProgress.done()
        }
      }
    }
  } else {
    // 6. 无 Token → 检查白名单
    const whiteList = ['/login', '/auth-redirect', '/VerifyPhone', '/ResetPassword']
    if (whiteList.indexOf(to.path) !== -1) {
      next()  // 白名单页面放行
    } else {
      // 从邮箱链接进入时带上原页面地址
      if (to.fullPath.includes('flag=email')) {
        next(`/login?redirect=${to.fullPath}`)
      } else {
        next('/login')
      }
    }
  }
})

router.afterEach((to) => {
  if (getToken()) {
    // 更新当前高亮的主菜单 ID（用于侧边栏高亮）
    store.dispatch('permission/findCurrentMainMenuId', { path: to.path })
  }
  NProgress.done()  // 关闭顶部进度条
})
```

**守卫流程图**：

```
用户访问任意页面
       ↓
   URL 有 ticket？（第三方 SSO 入口）
    ├─ Yes → thirdPartyAuthority(ticket) 验证
    │         ├─ isFirstLanding=0 → 跳转首页
    │         └─ 首次登录 → 跳转重置密码页
    └─ No  → 检查 Cookie 中的 Token
             ├─ 无 Token
             │    ├─ 在白名单 → next() 放行
             │    └─ 不在白名单 → next('/login')
             └─ 有 Token
                  ├─ 访问 /login → next('/') 跳转首页
                  └─ 访问其他页
                       ├─ 有 roles → next() 直接放行
                       └─ 无 roles → getInfo() + generateRoutes() + start() + replace
```

**关键设计点**：

| 设计 | 作用 |
| --- | --- |
| `ticket` 参数 | 支持从钉钉/企业微信等 SSO 入口免登录 |
| `whiteList` | 登录/重置密码等页面无需权限即可访问 |
| `hasRoles` 判断 | 避免每次路由切换都重新请求用户信息和权限 |
| `generateRoutes` | 从后端 API 获取菜单树，动态注册路由 |
| `start()` | qiankun 微前端启动，注册子应用生命周期 |
| `replace: true` | 动态路由注入后重新触发路由匹配，避免刷新 404 |
| `findCurrentMainMenuId` | 路由切换后更新侧边栏高亮状态 |

## 12. 组件封装的设计原则与最佳实践

组件封装是现代前端开发的**核心能力**，决定了项目的可维护性、可扩展性和开发效率。面试官常问「如何封装一个可复用的组件」，考察的不仅是代码能力，更是设计思维。

### 12.1 组件封装的设计原则

#### SOLID 原则在前端组件中的应用

| 原则 | 前端组件实现 | 示例 |
|------|--------------|------|
| **S** 单一职责 | 一个组件只做一件事 | `<Button>` 只负责渲染按钮，不处理业务逻辑 |
| **O** 开闭原则 | 对扩展开放，对修改关闭 | 通过 `props` 和 `slots` 扩展，不修改组件内部 |
| **L** 里氏替换 | 子类可替换父类 | `<BaseDialog>` 可被 `<ConfirmDialog>` 无缝替换 |
| **I** 接口隔离 | 不强迫组件实现不需要的接口 | 拆分大组件为多个职责单一的小组件 |
| **D** 依赖倒置 | 依赖抽象而非具体实现 | 组件接收 `onSubmit` 回调，不关心具体实现 |

#### 其他重要原则

**DRY（Don't Repeat Yourself）**：  
重复的 UI 逻辑或样式提取为组件或 mixin/composable。

**KISS（Keep It Simple, Stupid）**：  
避免过度设计，优先使用简单方案。

**Composition over Inheritance**：  
优先使用组合而非继承（Vue3 Composition API、React Hooks）。

### 12.2 组件封装的层次结构

```
├── 基础组件（无业务逻辑）
│   ├── Button、Input、Select
│   └── 特点：纯 UI，高度可复用
├── 业务组件（轻度业务耦合）
│   ├── SearchBar、Pagination
│   └── 特点：可配置，适合多业务场景
├── 页面组件（重度业务耦合）
│   ├── UserProfile、OrderList
│   └── 特点：特定业务，复用性低
└── 高阶组件/组合式函数
    ├── withLoading、withAuth
    └── 特点：增强功能，不直接渲染 UI
```

### 12.3 组件封装实战案例

#### 案例一：弹窗组件封装

**需求**：统一管理弹窗的打开/关闭、动画、遮罩层、标题和内容。

```vue
<!-- BaseModal.vue -->
<template>
  <transition name="fade">
    <div v-if="visible" class="modal-overlay" @click="handleOverlayClick">
      <div class="modal-container" :style="containerStyle" @click.stop>
        <div class="modal-header">
          <slot name="title">
            <h3>{{ title }}</h3>
          </slot>

        <div class="modal-body">

        </div>
        <div class="modal-footer">
          <slot name="footer">
            <button @click="close">取消</button>
            <button @click="$emit('confirm')">确认</button>
          </slot>
        </div>
      </div>
    </div>
  </transition>
</template>

<script setup>
const props = defineProps({
  visible: { type: Boolean, default: false },
  title: { type: String, default: '' },
  width: { type: String, default: '600px' },
  closeOnOverlayClick: { type: Boolean, default: true }
})

const emit = defineEmits(['update:visible', 'close', 'confirm'])

const containerStyle = computed(() => ({
  width: props.width
}))

  emit('update:visible', false)
  emit('close')
}

function handleOverlayClick() {
  if (props.closeOnOverlayClick) {

  }
}
```
```vue
</script>
```

**使用组合式 API 封装表单逻辑**：

```javascript
// useForm.js
import { ref, computed } from 'vue'

export function useForm(initialValues = {}, rules = {}) {
  const values = ref({ ...initialValues })
  const errors = ref({})
  const isSubmitting = ref(false)
  
  const isValid = computed(() => {
    return Object.keys(errors.value).every(key => !errors.value[key])
  })
  
  function validateField(name, value) {
    const rule = rules[name]
    if (!rule) return ''
    
    if (rule.required && !value) return '必填项'
    if (rule.minLength && value.length < rule.minLength) 
      return `至少${rule.minLength}个字符`
    if (rule.pattern && !rule.pattern.test(value)) 
      return rule.message || '格式错误'
    
    return ''
  }
  
  function validateAll() {
    const newErrors = {}
    Object.keys(values.value).forEach(key => {
      const error = validateField(key, values.value[key])
      if (error) newErrors[key] = error
    })
    errors.value = newErrors
    return Object.keys(newErrors).length === 0
  }
  
  async function submit(callback) {
    if (!validateAll() || isSubmitting.value) return
    
    isSubmitting.value = true
    try {
      await callback(values.value)
    } finally {
      isSubmitting.value = false
    }
  }
  
  return {
    values,
    errors,
    isSubmitting,
    isValid,
    validateField,
    validateAll,
    submit
  }
}
```

#### 案例三：表格组件封装（支持分页、筛选）

**需求**：封装可复用的表格组件，支持分页、排序、筛选、自定义列渲染。

```vue
<!-- DataTable.vue -->
<template>
  <div class="data-table">
    <!-- 工具栏：搜索、筛选 -->
    <div class="toolbar">
      <slot name="toolbar">
        <input v-model="searchText" placeholder="搜索..." />
        <slot name="filters"></slot>
      </slot>
    </div>
    
    <!-- 表格主体 -->
    <table>
      <thead>
        <tr>
          <th v-for="col in columns" :key="col.key">
            <div class="column-header" @click="handleSort(col.key)">
              {{ col.title }}
              <span v-if="sortBy === col.key">
                {{ sortOrder === 'asc' ? '↑' : '↓' }}
              </span>
            </div>
          </th>
        </tr>
      </thead>
      <tbody>
        <tr v-for="row in paginatedData" :key="row.id">
          <td v-for="col in columns" :key="col.key">
            <slot :name="`col-${col.key}`" :row="row" :value="row[col.key]">
              {{ formatCell(row[col.key], col) }}
            </slot>
          </td>
        </tr>
      </tbody>
    </table>
    
    <!-- 分页器 -->
    <div class="pagination">
      <button @click="prevPage" :disabled="currentPage === 1">上一页</button>
      <span>第 {{ currentPage }} 页 / 共 {{ totalPages }} 页</span>
      <button @click="nextPage" :disabled="currentPage === totalPages">下一页</button>
    </div>
  </div>
</template>

<script setup>
import { computed, ref } from 'vue'

const props = defineProps({
  data: { type: Array, default: () => [] },
  columns: { type: Array, required: true },
  pageSize: { type: Number, default: 10 }
})

const searchText = ref('')
const sortBy = ref('')
const sortOrder = ref('asc') // 'asc' | 'desc'
const currentPage = ref(1)

// 计算属性：筛选、排序、分页
const filteredData = computed(() => {
  if (!searchText.value) return props.data
  
  return props.data.filter(row => {
    return props.columns.some(col => {
      const value = String(row[col.key] || '')
      return value.toLowerCase().includes(searchText.value.toLowerCase())
    })
  })
})

const sortedData = computed(() => {
  if (!sortBy.value) return filteredData.value
  
  return [...filteredData.value].sort((a, b) => {
    const aVal = a[sortBy.value]
    const bVal = b[sortBy.value]
    
    if (sortOrder.value === 'asc') {
      return aVal > bVal ? 1 : -1
    } else {
      return aVal < bVal ? 1 : -1
    }
  })
})

const totalPages = computed(() => 
  Math.ceil(sortedData.value.length / props.pageSize)
)

const paginatedData = computed(() => {
  const start = (currentPage.value - 1) * props.pageSize
  const end = start + props.pageSize
  return sortedData.value.slice(start, end)
})

function handleSort(key) {
  if (sortBy.value === key) {
    sortOrder.value = sortOrder.value === 'asc' ? 'desc' : 'asc'
  } else {
    sortBy.value = key
    sortOrder.value = 'asc'
  }
  currentPage.value = 1
}

function prevPage() {
  if (currentPage.value > 1) currentPage.value--
}

function nextPage() {
  if (currentPage.value < totalPages.value) currentPage.value++
}

function formatCell(value, column) {
  if (column.formatter) return column.formatter(value)
  if (column.type === 'date' && value) return new Date(value).toLocaleDateString()
  return value ?? '-'
}
</script>
```

### 12.4 组件封装的常见面试题

#### Q1：如何设计一个可复用的组件？
**考察点**：设计思维、抽象能力、API设计

**回答要点**：
1. **明确职责**：组件应该做什么、不做什么
2. **合理抽象**：提取共性，通过 props/slots 提供灵活性
3. **良好API**：清晰的 props、events、slots 定义
4. **样式隔离**：使用 scoped CSS 或 CSS Modules
5. **文档齐全**：使用示例、类型定义、使用说明

#### Q2：组件通信有哪些方式？各适用什么场景？
**考察点**：Vue/React 组件通信知识体系

**回答要点**：
1. **父子通信**：`props` / `emit` - 直接关系
2. **兄弟通信**：事件总线 / 状态管理 - 间接关系  
3. **跨级通信**：`provide`/`inject` / Context API - 深层嵌套
4. **全局状态**：Vuex / Pinia / Redux - 应用级共享

#### Q3：如何处理组件的副作用（如请求、定时器）？
**考察点**：生命周期、资源管理、内存泄漏

**回答要点**：
1. **在正确时机执行**：`mounted` / `useEffect` 中发起请求
2. **及时清理**：`beforeUnmount` / `cleanup` 中清除定时器、取消请求
3. **错误处理**：try-catch 或 Promise.catch 处理异常
4. **避免重复请求**：防抖、缓存、请求锁

#### Q4：如何实现组件的懒加载？
**考察点**：性能优化、代码分割

**回答要点**：
1. **动态导入**：`() => import('./HeavyComponent.vue')`
2. **路由懒加载**：Vue Router 的 component 配置
3. **条件渲染**：`<Suspense>` 配合异步组件
4. **骨架屏**：加载时显示占位内容

#### Q5：如何测试组件？
**考察点**：测试能力、质量意识

**回答要点**：
1. **单元测试**：使用 Jest + Vue Test Utils / React Testing Library
2. **测试内容**：渲染、用户交互、props 变化、事件触发
3. **覆盖率**：语句、分支、函数、行覆盖率
4. **快照测试**：确保 UI 不意外改变

### 12.5 组件封装的最佳实践

#### 1. Props 设计原则
- **明确类型**：使用 TypeScript 或 prop-type 定义类型
- **合理默认值**：提供安全的默认值
- **命名规范**：kebab-case（模板） / camelCase（脚本）
- **单向数据流**：props 只读，通过 emit 更新

#### 2. 事件设计原则
- **命名规范**：`update:xxx`（v-model）、`click`、`change`
- **参数明确**：传递必要的数据，避免传递整个事件对象
- **避免滥用**：只在必要时定义事件

#### 3. Slot 使用技巧
- **命名插槽**：明确作用域，提供灵活性
- **作用域插槽**：向父组件暴露数据
- **后备内容**：提供合理的默认内容

#### 4. 样式处理
- **Scoped CSS**：避免样式污染
- **CSS Modules**：更彻底的隔离
- **CSS-in-JS**：动态样式、主题支持
- **BEM 命名**：提高可读性和可维护性

#### 5. 性能优化
- **避免不必要的渲染**：`v-memo` / `React.memo`
- **懒加载**：按需加载组件
- **虚拟列表**：大数据量时使用虚拟滚动
- **防抖节流**：高频操作优化

### 12.6 组件封装检查清单

在封装组件前，对照检查以下问题：

- [ ] **职责是否单一**？组件是否只做一件事
- [ ] **API 是否清晰**？props/events/slots 定义是否明确
- [ ] **是否易于使用**？调用方是否需要了解内部实现
- [ ] **是否易于扩展**？能否通过配置满足新需求
- [ ] **样式是否隔离**？会不会影响其他组件
- [ ] **性能是否达标**？有无不必要的渲染或计算
- [ ] **错误处理是否完备**？边界情况是否有处理
- [ ] **文档是否齐全**？有无使用示例和类型定义
- [ ] **测试是否覆盖**：关键功能是否有测试
- [ ] **可访问性是否考虑**：是否支持键盘操作、屏幕阅读器

### 策略模式 — 表单验证/权限判断

```javascript
const validateStrategies = {
  required: (value) => value ? '' : '必填',
  email: (value) => /^\w+@\w+.\w+$/.test(value) ? '' : '邮箱格式错误',
  mobile: (value) => /^1[3-9]\d{9}$/.test(value) ? '' : '手机号格式错误',
  minLength: (value, len) => value.length >= len ? '' : `至少${len}位`,
};

// 验证器
class Validator {
  constructor() {
    this.rules = [];
  }

  add(value, rule) {
    this.rules.push({ value, rule });
  }

  validate() {
    for (const { value, rule } of this.rules) {
      const fn = validateStrategies[rule.type];
      const error = fn(value, rule.param);
      if (error) return error;
    }
    return '';
  }
}
```

**优势**：新增验证规则只需添加一个策略函数，不修改现有代码（开闭原则）。

### 观察者模式 / 发布订阅 — 事件总线

```javascript
class EventBus {
  constructor() {
    this.events = {};
  }

  on(event, callback) {
    if (!this.events[event]) this.events[event] = [];
    this.events[event].push(callback);
  }

  emit(event, ...args) {
    (this.events[event] || []).forEach(fn => fn(...args));
  }

  off(event, callback) {
    this.events[event] = this.events[event].filter(fn => fn !== callback);
  }
}

export const bus = new EventBus();

// 组件 A
bus.on('user:login', (user) => console.log('登录用户:', user));

// 组件 B
bus.emit('user:login', { name: '张三' });
```

```javascript
function createCacheProxy(fn) {
  const cache = new Map();

    const key = JSON.stringify(args);
    if (cache.has(key)) {
      console.log('命中缓存:', key);
      return cache.get(key);
    }
    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}
```
